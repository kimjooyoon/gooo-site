Three different outcomes

StateMeaning within a specified contract
CLOSEDThe stated obligation has supporting evidence.
UNKNOWNEvidence is missing, stale, ambiguous, or blocked by a dependency.
REFUTEDAn observed counterexample contradicts the claim.

Unknown records should retain the stage, step, reason, class, next operation, and blocking dependencies. Known failure must not disappear just because a later event is malformed.

Recent bounded progress

  • Syntax registration: 6/6 original acceptance obligations reconciled. This is an issue-specific denominator, not six language-completeness points.
  • Release execution isolation merged; the associated cache-poisoning alert was subsequently reported fixed.
  • Bounded observation of pending predecessor evidence merged. Pending is not success.
  • Callback counterexample preservation merged. Incomplete input does not erase an already observed failure.

What this does not establish

External product utility, arbitrary semantic correctness, and comparative performance improvements remain unproven by these results. Claims of lower time or memory require a comparable before/after pair.

Some PRs retain classified Guardian failures despite a passing development-route proof. We do not label all checks green or use these proofs as release authorization.
